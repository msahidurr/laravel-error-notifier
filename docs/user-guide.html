01What it is

Laravel Error Notifier sends a message to your team every time your Laravel app reports an exception. It plugs into Laravel's own error handling, so once it is installed and switched on, you don't call it anywhere in your code.

Each alert says what failed, where (file and line), and who hit it (request, user, IP or artisan command). It can go to one or several channels at once: Telegram, Slack, Mattermost, Discord, Google Chat, Microsoft Teams, email, PagerDuty or any webhook.

Requirements: PHP 8.1 or newer and Laravel 9, 10, 11 or 12. Each channel needs its own account or webhook URL; nothing else is required.

02Install and quick start

You can have Telegram alerts working in about five minutes.

  1. Install the package in your Laravel app:
    bash
    $ composer require msahidurr/laravel-error-notifier
    The service provider and the ErrorNotifier facade register themselves; there is nothing to add to config/app.php.
  2. Add these lines to .env (the Telegram setup steps show how to get the token and chat ID):
    .env
    ERROR_NOTIFIER_ENABLED=true
ERROR_NOTIFIER_CHANNELS=telegram
ERROR_NOTIFIER_TITLE="APIs Error"

TELEGRAM_BOT_TOKEN=123456:ABC-your-bot-token
TELEGRAM_ERROR_CHAT_ID=-1001234567890
  3. If your app caches its config, rebuild it:
    bash
    $ php artisan config:cache
  4. Send a test message:
    bash
    $ php artisan error-notifier:test
✔ telegram: sent
    You should see telegram: sent in the terminal and a test alert in the chat.
Note

Real errors are not sent from the local and testing environments by default, so you won't get alerts while developing. The test command works in every environment.

Pick the channel your team already reads; add PagerDuty only if someone is on call. List the channels you want in ERROR_NOTIFIER_CHANNELS, separated by commas (for example telegram,slack,mail). Every report goes to every listed channel.

04Channel setup step by step

Each channel needs one credential from the service. Add it to .env, add the channel name to ERROR_NOTIFIER_CHANNELS, then check it with php artisan error-notifier:test --channel=<name>.

TG

Telegram

telegram
  1. In Telegram, open @BotFather, send /newbot, and copy the token → TELEGRAM_BOT_TOKEN.
  2. Add the bot to your group and send any message in the group.
  3. Open https://api.telegram.org/bot<TOKEN>/getUpdates in a browser and copy chat.id → TELEGRAM_ERROR_CHAT_ID. Group IDs start with -.
  4. Optional: for a forum group, set TELEGRAM_ERROR_THREAD_ID to the topic ID.
SL

Slack

slack
  1. Create a Slack app at api.slack.com/apps and turn on Incoming Webhooks.
  2. Click Add New Webhook to Workspace, pick the channel, and copy the URL → SLACK_ERROR_WEBHOOK_URL.
MM

Mattermost

mattermost
  1. Go to Integrations → Incoming Webhooks → Add Incoming Webhook and pick the channel.
  2. Copy the URL → MATTERMOST_ERROR_WEBHOOK_URL.
DC

Discord

discord
  1. Open the channel's Edit Channel → Integrations → Webhooks → New Webhook.
  2. Click Copy Webhook URL → DISCORD_ERROR_WEBHOOK_URL.
  3. Optional: DISCORD_ERROR_USERNAME sets the sender name.

Mentions like @everyone inside error messages never ping anyone.

GC

Google Chat

google_chat
  1. In the space, open Apps & integrations → Webhooks → Add webhook.
  2. Copy the URL → GOOGLE_CHAT_ERROR_WEBHOOK_URL.
  3. Optional: set GOOGLE_CHAT_ERROR_THREAD_KEY=errors to keep all alerts in one thread instead of filling the space.
MT

Microsoft Teams

teams
  1. In the channel, open Workflows and choose Post to a channel when a webhook request is received.
  2. Finish the template and copy the URL it gives you → TEAMS_ERROR_WEBHOOK_URL.

The old Incoming Webhook connector URLs were switched off by Microsoft in May 2026 and will not work. Alerts appear from "Flow bot"; the sender name can't be changed.

EM

Email

mail
  1. Make sure your app can already send mail (the MAIL_* settings).
  2. Set ERROR_NOTIFIER_MAIL_TO to one or more addresses, separated by commas.
  3. Optional: ERROR_NOTIFIER_MAIL_FROM and ERROR_NOTIFIER_MAILER (for example a separate SMTP mailer).

Sending mail can take a few seconds, so turn on the queue when you use email.

WH

Webhook

webhook
  1. Set ERROR_NOTIFIER_WEBHOOK_URL to the URL that should receive the alerts.
  2. Optional: set ERROR_NOTIFIER_WEBHOOK_SECRET. Each request then carries X-Error-Notifier-Signature: sha256=<hmac>, so the receiver can check it came from your app.

The body is JSON: title, app, environment, exception, message, file, line, context, trace, time, fingerprint.

PD

PagerDuty

pagerduty
  1. Open the service → Integrations → Add integration → Events API V2.
  2. Copy the Integration Key → PAGERDUTY_ROUTING_KEY.
  3. Optional: PAGERDUTY_SEVERITY (critical, error, warning or info; default error).

Repeats of the same error update one incident instead of opening a new one each time.

05Controlling what gets sent

Every error goes through the same checks in order; the first "no" stops it. The first three apply once per error, the last two separately for each channel.

Environments

local and testing never send real errors. Change the list with ignored_environments in the published config.

Paths

Add URL paths that should never alert, for example a noisy OTP endpoint. Each path also covers everything under it:

config/error-notifier.php
'excluded_paths' => [
    'api/v2/otp/generate',
    'health',
],

Exception types

404s, failed logins and validation errors are skipped by default. Add your own (subclasses count too):

config/error-notifier.php
'excluded_exceptions' => [
    \Symfony\Component\HttpKernel\Exception\NotFoundHttpException::class,
    \Illuminate\Auth\AuthenticationException::class,
    \Illuminate\Validation\ValidationException::class,
    \App\Exceptions\PaymentDeclinedException::class,
],

Duplicates

The same error (same type, file, line and message) is sent once per 60 seconds. Change it with ERROR_NOTIFIER_THROTTLE (seconds; 0 turns it off).

Per-channel filters and limits

Each channel can take only some errors, skip some, and cap messages per minute. For example, everything goes to Slack, but PagerDuty only pages for database errors:

config/error-notifier.php
'drivers' => [
    'slack' => [
        'webhook_url' => env('SLACK_ERROR_WEBHOOK_URL'),
        'rate_limit' => 50,
        'except_exceptions' => [\App\Exceptions\NoisyException::class],
    ],
    'pagerduty' => [
        'routing_key' => env('PAGERDUTY_ROUTING_KEY'),
        'only_exceptions' => [\Illuminate\Database\QueryException::class],
    ],
],

06Sending from a queue

Turn on the queue if you use email or more than one channel. Without it, alerts are sent while Laravel handles the failing request, and each channel can add up to 5 seconds (10 for Teams) to that request.

.env
ERROR_NOTIFIER_QUEUE=true
ERROR_NOTIFIER_QUEUE_CONNECTION=redis   # optional, defaults to QUEUE_CONNECTION
ERROR_NOTIFIER_QUEUE_NAME=alerts        # optional
Needed

A queue worker must be running (php artisan queue:work, usually under Supervisor). Without one, alerts wait in the queue and never arrive.

  • If the alert can't be queued (for example Redis is the thing that's down), it is sent immediately instead, so you still hear about it.
  • Alerts are still queued when the error rolls back a database transaction, even on a queue connection set to after_commit.
  • Failed alert jobs are not retried, so a broken channel never sends you the same alert twice.
  • The alert keeps the original details: the request URL or artisan command, not queue:work.

07Configuration reference

Most apps only need .env. Publish the config file when you need settings that have no env variable: excluded paths, excluded exceptions, per-channel filters, ignored environments or stack trace lines.

bash
$ php artisan vendor:publish --tag=error-notifier-config

This creates config/error-notifier.php in your app, and Laravel uses it from then on. After any change, run php artisan config:cache if your app caches config.

Updates

Your published file is not updated when the package is. New top-level settings still work with their defaults, but new channels or channel settings inside drivers only apply once you add them to your file. To see the latest defaults, commit your file and re-publish with --force, then copy back your changes.

08Reading an alert

Every alert has the same fields, whatever the channel; only the layout differs (see the example at the top). Start with Exception and Message to see what broke, then File to find it in the code.

FieldMeaning
TitleYour ERROR_NOTIFIER_TITLE, to tell apps apart
ProjectYour APP_NAME
EnvironmentYour APP_ENV
ExceptionThe type of error
MessageWhat went wrong, cut at 1,000 characters
RequestThe URL that failed (web errors only)
UserLogged-in user ID and name, or Guest
IPVisitor's IP address
CommandThe artisan command that failed (console and queue errors only)
File / LineWhere it happened, relative to the project root
TraceFirst lines of the stack trace, if trace_lines is above 0
TimeWhen it happened, in your app's timezone

Very long messages and traces are shortened to fit each service's size limit; the full error is always in storage/logs/laravel.log.

09Troubleshooting

Start with php artisan error-notifier:test: it prints sent or the exact error for each channel. Delivery problems are also logged in storage/logs/laravel.log as Error notifier failed with the channel name.

ProblemLikely causeFix
Test works, real errors never arriveERROR_NOTIFIER_ENABLED is not true, or APP_ENV is local/testingSet ERROR_NOTIFIER_ENABLED=true; check ignored_environments
Changes in .env have no effectConfig is cachedRun php artisan config:cache
<channel> is not configuredThe channel's env variable is emptyAdd it to .env, then rebuild the config cache
Driver [name] not supportedTypo in ERROR_NOTIFIER_CHANNELS, or a new channel missing from an older published configCheck the spelling (google_chat, not googlechat); add the channel under drivers in your published file
Telegram chat not foundWrong chat ID, or the bot isn't in the groupAdd the bot to the group, send a message, read getUpdates again
Teams returns an error or nothing appearsAn old Office 365 connector URLCreate a new Workflows webhook
Some errors never arriveExcluded exception type (404, login, validation), excluded path, or the same error repeated within 60 secondsExpected; adjust excluded_exceptions, excluded_paths or ERROR_NOTIFIER_THROTTLE
rate limit reached in the logMore errors per minute than the channel's limitFix the error flood; raise rate_limit only if the service allows it
Queue is on but nothing arrivesNo queue worker runningStart php artisan queue:work (or check Supervisor)
The same error arrives twiceBoth this package and an old manual call in Handler.php report itRemove the old manual call

10Security and good practice

Treat every token and webhook URL as a password: anyone who has one can post into your channel.

  • Keep secrets in .env only. Never put real tokens or webhook URLs in config/error-notifier.php, .env.example or git.
  • Logs stay clean. When a channel fails, the logged error has bot tokens, webhook paths and routing keys replaced with ***.
  • Alerts contain personal data. They include user IDs and names, IP addresses and URLs with query strings. Send them only to private channels your team controls. Turn off include_user or include_ip if your privacy policy requires it.
  • Exception messages can contain secrets. Some libraries put passwords or API keys in error text. Add those exception types to excluded_exceptions, or keep trace_lines at 0.
  • No accidental pings. Text inside an error can't trigger @everyone, @channel or formatting in Slack, Discord, Mattermost or Teams.
  • Verify webhook calls. When using the webhook channel, set ERROR_NOTIFIER_WEBHOOK_SECRET and check the signature on the receiving side.
  • Rotate on leaks. If a token or webhook URL is ever exposed, create a new one in the service and update .env; the old one keeps working until you delete it.
